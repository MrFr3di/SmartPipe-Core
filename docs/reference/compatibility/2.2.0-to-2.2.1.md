# SmartPipe 2.2.0 → 2.2.1 compatibility

The published SmartPipe 2.2.0 package set is the compatibility baseline for the
2.2.1 PATCH servicing line.

## Contract

- All 20 packages published in 2.2.0 participate in the synchronized 2.2.1
  package version.
- There is no intentional public API removal or incompatible package movement.
- The API surface published in 2.2.0 is recorded in each package's
  `PublicAPI.Shipped.txt`.
- Native Package Validation compares 2.2.1 candidates with published 2.2.0
  packages.
- The immutable 2.1.2 baseline remains historical evidence for the earlier
  2.1.2 → 2.2.0 transition and is not regenerated.
- The six intentional 2.1.2 → 2.2.0 facade suppressions are retained in
  `CompatibilitySuppressions.2.1.2-to-2.2.0.xml` and are loaded only when that
  historical baseline is explicitly selected; they are not active against 2.2.0.

## Additive Core API in 2.2.1

The release retains published 2.2.0 signatures and adds the following opt-in
interfaces under the explicit PATCH exception in `VERSIONING.md`:

- `PipelineRuntimeOptions.RetryBudget` / `RetryBudgetOptions` for per-run retry tokens.
- `RetryPolicy.Jitter` / `RetryJitterMode` for optional full retry jitter.
- `PipelineRuntimeOptions.TimedAttemptAdmission` / `TimedAttemptAdmissionOptions`
  for combined active-plus-detached timed execution admission.
- `CircuitBreakerPolicy.SamplingMode`, `CircuitBreakerOptions.SamplingMode`,
  `CircuitBreakerSamplingMode` and `SamplingBucketCount` for optional buckets.

Existing configurations retain null retry/admission settings, deterministic
jitter (`None`) and exact circuit-breaker sampling (`Exact`). The opt-in
bucketed mode may retain samples in one partial oldest bucket, so the failure
ratio and even the threshold decision may differ from exact sampling.

These are additive APIs; no previous public method is removed or moved.
Compatibility is a separate release-mode validation against *published*
2.2.0 binaries, not a claim based solely on compiling this source tree.

## Servicing exceptions

Security and privacy hardening may remove sensitive values from logs without
changing the public API contract. In 2.2.1, the legacy Dapper source completion
log stops emitting raw SQL text at Information level.

See the [2.2.1 servicing migration](../../migration/2.2.1-integration-packages.md),
[2.2.1 servicing notes](../../releases/2.2.1.md), and
[CHANGELOG](../../../CHANGELOG.md).
