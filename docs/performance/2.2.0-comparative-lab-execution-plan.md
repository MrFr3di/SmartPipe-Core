# 2. CI cost model for this public repository

## 2.1 What is actually quota-limited

As of September 2026:

- standard GitHub-hosted runners are free for public repositories;
- paid larger runners are not used;
- the default Actions cache allowance is 10 GB per repository;
- caches not accessed for more than 7 days are eligible for removal;
- artifact storage is finite and therefore raw evidence must be short-lived.

The lab therefore optimizes for:

1. short feedback time;
2. low artifact/cache churn;
3. reproducibility;
4. not occupying concurrency with obsolete runs;
5. evidence quality.

It does **not** remove useful checks merely to save public-repository runner minutes.

## 2.2 Runner selection

Primary CI runner:

```yaml
runs-on: ubuntu-24.04
```

Why:

- explicit OS family is more reproducible than `ubuntu-latest`;
- it is a standard public GitHub-hosted runner;
- no paid larger runner is required;
- Linux is sufficient for the primary benchmark/stress harness;
- cross-platform behavioural correctness remains in the normal repository CI.

Do not add a Windows/macOS benchmark matrix merely for timing. It multiplies noise and
does not improve the primary A/B conclusion.

## 2.3 Self-hosted policy

Do not attach a persistent self-hosted runner to this public repository for
authoritative performance runs.

Authoritative controlled-machine runs should initially be executed outside GitHub
Actions using the same checked-in PerfLab commands. If later automation is required,
use a disposable isolated/JIT environment with a separate security design.

# 3. Cache design

## 3.1 What is cached

Exactly one dependency cache class is allowed in normal lab CI:

```text
NuGet global-packages
```

Use `actions/setup-dotnet` built-in caching:

```yaml
env:
  NUGET_PACKAGES: ${{ github.workspace }}/.nuget/packages

- uses: actions/setup-dotnet@a98b56852c35b8e3190ac28c8c2271da59106c68 # v6.0.0
  with:
    global-json-file: global.json
    cache: true
    cache-dependency-path: '**/packages.lock.json'
```

Do not add a second `actions/cache` for the same NuGet directory.

## 3.2 What is never cached

Never dependency-cache:

- `bin/`;
- `obj/`;
- baseline SmartPipe package files used as evidence;
- candidate SmartPipe package files;
- local target feeds;
- BenchmarkDotNet artifacts;
- normalized benchmark results;
- stress output;
- soak output;
- `dotnet-trace` traces;
- gcdumps;
- generated comparison reports.

Reason: these are either reproducibility evidence or build outputs. Restoring them from
an opaque cache can make a later run measure stale code.

## 3.3 Cache-key evolution

Bootstrap uses the repository-wide lock-file hash because this already matches current
CI and is safe.

PERF-02 must measure cache churn. If the lab becomes independent enough, narrow the
dependency path to the PerfLab and target-adapter lock files. The change is accepted only
when it cannot hide a dependency change used by the lab.

## 3.4 Cache security

- cache never contains credentials;
- cache hit does not establish target identity;
- target SHA and package hashes are always independently checked;
- checkout always uses `persist-credentials: false`;
- workflow permissions remain read-only;
- no `pull_request_target` benchmark execution.

# 5. CI topology

## 5.1 Push smoke

Trigger only when lab-relevant paths change.

Current implementation:

```text
checkout
  ↓
validate manifests/contracts
  ↓
setup .NET + NuGet cache
  ↓
locked restore benchmark project
  ↓
Release build
  ↓
BenchmarkDotNet Dry definition benchmark
```

Maximum job timeout: 15 minutes.

Superseded push/smoke runs are canceled with workflow concurrency.

## 5.2 Manual benchmark smoke

The workflow declares `workflow_dispatch(mode=benchmark-smoke)`, but GitHub enables
manual dispatch only after that workflow file exists on the default branch. During the
experimental-branch bootstrap, push smoke is therefore the executable CI path. Do not
modify `main` merely to unlock manual dispatch.

After the workflow is accepted on the default branch,
`workflow_dispatch(mode=benchmark-smoke)` runs the same dry benchmark and uploads the
small BDN artifact for 3 days.

This mode verifies:

- benchmark discovery;
- generated BDN project compilation;
- process execution;
- exporter/artifact path;
- CI image compatibility.

It is not performance evidence.

## 5.3 Future full A/B job

The full A/B job must execute baseline and candidate on **the same GitHub runner VM**.

Forbidden:

```text
matrix:
  target: [2.1.2, 2.2.0]
```

for performance comparison, because two matrix legs may get different host hardware/noise.

Required order:

```text
A1 → B1 → B2 → A2
```

or another deterministic counter-balanced sequence.

One job:

1. checkout harness;
2. checkout/materialize exact candidate;
3. provision verified baseline packages;
4. pack verified candidate packages;
5. build both isolated benchmark executables from the same benchmark sources;
6. correctness precheck;
7. A1/B1/B2/A2;
8. normalize;
9. compare;
10. upload short-lived raw evidence.

## 5.4 Stress

Stress is manual during bootstrap.

It uses fixed work rather than elapsed-time loops:

- item count;
- run count;
- concurrency;
- deterministic failure schedule;
- deterministic cancellation point;
- fixed seed.

A future short stress smoke may be allowed on push only after it is deterministic and
bounded.

## 5.5 Soak

Soak is never a normal PR check.

Profiles:

- developer: 30 min;
- standard: 60 min;
- extended: 120 min.

GitHub-hosted soak may be useful as informational leak evidence, but authoritative
memory-slope conclusions should come from a controlled machine.

# 15. PERF-09 — Soak and leak analysis

## PERF-09.1 — Sampling

After warmup record periodic samples:

- managed heap;
- working set;
- Gen2 count;
- allocation rate;
- threads;
- ThreadPool queue;
- active runs;
- resources owned by scenario.

## PERF-09.2 — Leak decision

Do not fail simply because working set rises once.

Look for:

- persistent post-warmup slope;
- unreleased run/resource count;
- repeated growth after GC stabilization;
- context/connection/file handle retention;
- inability to return to bounded steady state.

## PERF-09.3 — End-of-run invariant

After shutdown:

- no active SmartPipe run;
- no owned DB context/connection;
- no owned stream;
- no pending test task;
- no unexpected exception;
- final counter reconciliation succeeds.
