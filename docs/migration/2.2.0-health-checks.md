# Migrating health checks in 2.2.0

Existing 2.1 source and binaries continue to use `SmartPipe.Extensions.AddSmartPipeHealthCheck<TInput,TOutput>` unchanged.

Canonical DI definitions should install `SmartPipe.Extensions.HealthChecks`, retain the builder returned by `AddPipeline`, and register checks on it:

```csharp
var orders = services.AddSmartPipe().AddPipeline(orderDefinition);
orders.AddLiveness();
orders.AddReadiness();
```

The new API identifies checks by exact `PipelineKey`, supports same-generic and concurrent pipelines, isolates options by registration name, and separates liveness from readiness. Choose `RegistrationOnly` for on-demand pipelines; keep `ActiveRunRequired` for continuously serving pipelines. Legacy health types remain physically implemented in `SmartPipe.Extensions` and are not type-forwarded.
