# Migrate CSV integrations to SmartPipe.Extensions.Csv 2.2.0

SmartPipe 2.2 moves `CsvFileSource<T>`, `CsvFileSink<T>`, and `CsvTransform<TInput,TOutput>` physically from `SmartPipe.Extensions.dll` to `SmartPipe.Extensions.Csv.dll` without changing their namespaces, constructors, defaults, or compiler-warning behavior.

New applications should reference `SmartPipe.Extensions.Csv` directly. Existing 2.x source and binaries may continue referencing `SmartPipe.Extensions`; the facade forwards the legacy identities and retains CsvHelper as a direct compatibility dependency while those forwarders exist, per ADR-0001.

For new pipelines prefer `CsvPipelineDefinitionBuilder.FromCsvFile` and `ToCsvFile`. The strict API is file-only and exposes a deliberately narrow RFC4180-style profile so record, field, and column bounds are enforceable before mapping. Advanced CsvHelper dialect configuration remains available only through the legacy compatibility types.

`SkipAndLog` requires an explicit borrowed `ILoggerFactory`. Append mode validates encoding/BOM and semantic header fields before writing. The strict sink accepts only CRLF, LF, or CR record terminators so its output remains readable by the strict source. Neither path promises public stream ownership, same-file concurrent writers, whole-file atomicity, or blanket NativeAOT compatibility.
