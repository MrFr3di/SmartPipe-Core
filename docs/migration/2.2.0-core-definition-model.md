# Migrating to the 2.2 Definition Model

SmartPipe.Core 2.2 adds an immutable generic definition model alongside the
shipped compatibility API. Existing non-generic definitions and builder
signatures remain available while the SP220-02 legacy adapter routes them into
the canonical runtime path.

Use `PipelineDefinitionBuilder.From` with an explicit `PipelineKey`, a typed
source `PipelineComponent<T>`, zero or more typed `Transform` calls, and either
`Build()` or terminal `To()`. Choose component ownership explicitly:

- `RuntimeOwned(factory)` creates, initializes, and disposes one instance per run.
- `ScopeOwned(factory)` creates and initializes through the activation services;
  the owning scope disposes the instance.
- `Borrowed(instance, initialize)` optionally initializes an existing instance,
  never disposes it, and makes the definition single-use.

Definitions containing borrowed observers or dead-letter resources are also
single-use. Dead-letter streams, serializers, and redactors remain caller-owned.

Activation validates identity, cancellation, the cached structural plan, and
required services before consuming a single-use definition. After a claim,
factory or initialization failure rolls back every already-created runtime-owned
component in reverse order. A clean rollback preserves the original exception;
cleanup failures are available through `PipelineActivationException` in cleanup
attempt order.

Start a canonical definition with `await definition.StartAsync(...)`. The method
returns after initialization, runtime `Running` state, and started-event
acceptance; startup failure is raised only after rollback. The returned run
exposes the exact definition key and run identifier, and concurrent disposal
calls share one cleanup operation.

The shipped `PipelineBuilder` signatures now use the sole internal legacy adapter
and the same generic compiler, activator, start operation, and executor. `Run`,
`To`, and `ToFactory` still return immediately; factory and initialization failures
are reported by `PipelineRun.Completion` after rollback.

Legacy instance registrations are intentionally hardened to single-use. This
includes sources, stages, sinks, observers, and instances that advertise the old
`Reusable` or `SingletonExternal` lifetime. A second or concurrent start fails
before activation and creates no resources. Migrate repeated runs to an all-factory
chain:

```csharp
PipelineBuilder
    .FromFactory(_ => new Source())
    .TransformFactory(_ => new Stage())
    .ToFactory(_ => new Sink());
```

Factory-only chains remain sequentially and concurrently reusable. Explicit IDs
and generated `pipeline-{guid:N}` keys are preserved, as are `stage-1` through
`stage-N`. Without `WithPipelineId`, an existing non-empty source envelope ID is
not overwritten. Do not add a second adapter or manually activate definition
components; those paths bypass readiness, ownership, and shared disposal.

The existing non-generic `PipelineDefinition` and `PipelineExecutionPlan` remain
callable metadata compatibility types. Their collections are now defensive
read-only copies, and duplicate stage IDs fail compilation before runtime work.
