# SmartPipe 2.2.1 servicing notes

SmartPipe 2.2.1 is the first servicing release after the published 2.2.0
package set. Its scope is backward-compatible correctness, security, reliability,
documentation, and release-engineering hardening. It does not introduce a new
package architecture or a new public feature surface.

## Current servicing scope

- Centralize the current release prefix and previous-stable baseline in
  `eng/SmartPipe.Versions.props`; package projects, package validation and
  release tooling consume that single machine-readable version catalog.
- Seal the public API that shipped in 2.2.0 as the analyzer baseline.
- Use the published 2.2.0 package set as the immediate Package Validation
  baseline for every package in the synchronized 2.2.1 train.
- Keep the immutable 2.1.2 baseline as historical evidence for the 2.2
  migration rather than as the servicing baseline.
- Keep CodeQL action phases on one version and group their Dependabot updates.
- Correct post-release support, security, SDK, and release documentation.
- Stop the legacy Dapper source completion log from emitting raw SQL text at
  Information level.
- Keep Entity Framework Core default failure logs payload-free: SmartPipe logs
  outcome metadata without attaching provider exception details, while the
  original exception still propagates to the caller.

## Compatibility with 2.2.0

The 2.2.1 line has no intentional public API break relative to the published
2.2.0 packages. Package Validation and PublicApiAnalyzers guard that contract.
The 2.1.2 compatibility evidence remains preserved separately for the original
2.2 transition.

See the [2.2.0 → 2.2.1 compatibility note](../reference/compatibility/2.2.0-to-2.2.1.md)
and the [2.2.0 → 2.2.1 servicing migration](../migration/2.2.1-integration-packages.md).
