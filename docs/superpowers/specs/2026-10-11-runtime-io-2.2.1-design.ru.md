# Runtime I/O: дизайн для 2.2.1

Дата: 2026-10-11. База: `4e550683415ac3bca59d28e7f6bfd910f20a597d`
(merge PR #152). Пользователь подтвердил результат: полный дизайн и план
I1/I2/O1/O2, без реализации на этом шаге. Последнее уточнение пользователя:
**вся работа остаётся в 2.2.1**, включая opt-in API I2.

## Контекст и решения

F1–F7 уже реализованы и смержены. Обозначения I/O взяты из
[runtime review](https://github.com/MrFr3di/SmartPipe-Core/blob/main/docs/maintainers/2.2.1/runtime-review-2026-10-08.md).
Приложенный июльский Stage 1 — исторический материал: его ограничения,
очередность и указания агентам не являются новым поручением пользователя.
Проверенные текущие файлы и [runtime contracts](../../runtime-contracts.md)
определяют исходное поведение.

Выбран постепенный путь: измерения, узкий internal supervisor, opt-in resilience,
затем измеренные оптимизации. Полная перепись executor одновременно с policies
затрудняет проверку ownership. Одни оптимизации не закрывают I2. Каждая часть
должна иметь самостоятельный diff и критерии приёмки.

Общее правило [VERSIONING.md](../../../VERSIONING.md) относит новые features
к MINOR. Для этой конкретной работы пользователь явно выбрал **2.2.1**:
это записанное исключение, а не основание убрать I2 или менять цель на 2.3.0.
Сохраняются `SmartPipeVersionPrefix=2.2.1` и previous-stable baseline `2.2.0`;
API/source/binary/package checks выполняются полностью. При реализации записать
это точечное исключение в versioning/release notes. Публикация релиза не входит
в текущий запрос на дизайн и план.

## Общие инварианты

1. Processing/mandatory-cleanup fault сохраняет приоритет над Abort/Cancel.
2. Ordinary workers завершаются до component cleanup и public Completion.
3. Detached execution, его CTS и observation остаются owned до действительного
   завершения. Finalization timeout может завершить Completion с ошибкой,
   а DisposeAsync продолжает ждать. ScopeOwned/Borrowed компоненты Core не освобождает.
4. Drain прекращает чтение source и сохраняет выполнение принятой работы.
5. Весь cleanup продолжается после throwing cancellation/disposal callbacks.
6. При выключенных новых policies сохраняются defaults, enum values,
   retry/event ordering, circuit-breaker EWMA и package boundaries.
7. Один resolved clock используется для deadlines, refill и waits.
   TimeProvider-backed clock допускает FakeTimeProvider; custom clock сохраняет
   существующий compatibility fallback.
8. Regression tests используют gates/barriers/channels, а timeouts только как
   ограничители зависания; новые тесты не координируются sleeps.
9. Независимое владение observation не зависит от права dispose компонента.

## I1: supervisor processing group

Извлечь проверенный F1 алгоритм parallel producer/worker join из
`TypedPipelineRuntime.cs` в internal `PipelineProcessingSupervisor`.
Это orchestration существующей processing group, а не registry каждой stage
invocation. Sequential путь не получает Task.Run и task registration на item.

Supervisor владеет linked worker CTS, первой worker ошибкой, cancellation callback
ошибками и unconditional join всех ordinary workers. Producer завершает bounded
input writer в finally. Worker fault немедленно останавливает source и siblings,
включая blocked output writes. SourceStopReason и классификация graceful source
stop остаются у executor; public lifecycle intent supervisor не меняет.

LateStageAttemptRegistry сохраняет отдельную state machine: seal после завершения
processing group, bounded finalization wait, затем unlimited observation join
при DisposeAsync. PipelineComponentLifetimeManager сохраняет activation ledger
и disposal rights. Observer pump остаётся owned dispatcher и joined его
CompleteAsync/DisposeAsync. Не регистрировать root RunCoreAsync в группе, которая
сама вызывается из RunCoreAsync: это создало бы self-join.

## I2a: shared retry budget

Добавить nullable `PipelineRuntimeOptions.RetryBudget` и immutable
`RetryBudgetOptions(int capacity, double refillTokensPerSecond)` с get-only
`Capacity` и `RefillTokensPerSecond`. Null выключает budget. Capacity > 0;
refill >= 0, finite; нулевой refill означает конечный budget на run.

На каждый run создаётся отдельный token bucket, общий для stages и envelopes,
изначально полный. Clock-based refill вычисляется lazy под коротким lock,
без timer/background task. У reusable definition разные starts не делят tokens.
Retry budget ограничивает суммарные реальные дополнительные execution starts;
первые attempts его не расходуют. Existing MaxRetries и StageTimeout продолжают
действовать одновременно с budget.

Перед RetryScheduled резервируется token. Отсутствие token завершает retry через
существующие RetryExhausted/OnRetryExhausted, сохраняя исходный stage error.
Предварительная reservation предотвращает oversubscription между workers.
После delay повторно проверяются cancellation, stage deadline, timed capacity
и breaker admission; callback выполняется только после успешного admission.
Token commit происходит непосредственно перед вызовом transformer, после
успешной доставки StageStarted. Cancellation, observer/callback fault, expired
deadline и breaker/admission rejection до invocation возвращают reservation.
Refill учитывает held reservations: free tokens + reserved tokens <= Capacity,
refill ceiling равен Capacity минус reservations. На reserve/commit/refund сначала
обновляется clock accounting; время blocked refill не накапливает будущий credit.
Так delayed retries не превращаются в burst больше Capacity при одновременном
commit. Возврат также ограничен Capacity. Уже начатый retry token не возвращает.

При выключенных policies используется прежняя последовательность событий.
В opt-in ветке preserve order: StageFailed → RetryScheduled → delay → admission
→ OnRetry → RetryAttempted → StageStarted → invocation. Новый rejection не
создаёт ложного StageStarted или dependency breaker sample. Исходный failure
sample существующей attempt остаётся. Budget denial отмечается internal
diagnostic reason `BudgetExhausted`; новый public event hierarchy не нужен.

## I2b: jitter

Добавить `RetryPolicy.Jitter { get; init; }` и enum `RetryJitterMode`:
`None = 0`, `Full = 1`. Constructor RetryPolicy и GetDelay сохраняют опубликованные
signatures и deterministic backoff. Runtime применяет jitter к одному вычисленному
base delay: Full равномерно выбирает целое количество ticks в `[0, baseTicks)`.
Результат не превышает MaxDelay; zero delay допустим как результат jitter.

Internal `IRetryRandomSource.NextInt64(long exclusiveUpperBound)` внедряется
в runtime retry planner; production использует Random.Shared, tests — scripted
source. Не создавать новый public RNG service. Delay выбирается один раз,
публикуется в RetryScheduled и используется для actual wait и budget/deadline
проверок. None не вызывает RNG. Snapshot копирует Jitter и валидирует enum
до activation. RetryOn не вызывается повторно для одной failed attempt.

## I2c: capacity для potentially detached executions

Добавить nullable `PipelineRuntimeOptions.TimedAttemptAdmission` и immutable
`TimedAttemptAdmissionOptions(int maxOutstandingAttempts,
TimedAttemptAdmissionMode mode)`; mode: `Wait = 0`, `Reject = 1`.
Null выключает admission; limit > 0; undefined enum отклоняется до activation.

Название намеренно описывает точную границу: ограничиваются **active timed +
detached timed executions вместе**, а не только уже detached tasks.
Каждая finite timed attempt резервирует slot до запуска user code. Иначе
несколько active attempts могли бы одновременно timeout и превысить late cap,
когда безопасно отклонить регистрацию уже невозможно.

При cooperative завершении slot освобождается после observation/CTS cleanup.
При detach reservation передаётся registry вместе с execution/CTS и освобождается
только после фактической observation. Timeout результата, finalization timeout
и отмена ожидания не освобождают slot за выполняющуюся операцию. Shutdown
отменяет admission waiters, но продолжает владеть ранее принятыми executions.

Wait ожидает освобождения slot с processing token и оставшимся StageTimeout.
Deadline включает admission wait. Истечение deadline возвращает существующий
timed-out stage outcome и применяет существующую timeout/exhaustion policy.
Без StageTimeout ожидание может продолжаться до release/cancellation.
Reject создаёт permanent SmartPipeError с Category `TimedAttemptAdmission`
и применяет OnPermanentFailure один раз, без скрытого retry, transformer call
и breaker dependency sample. Envelope terminal failure учитывается adaptive
как failed. Retry reservation возвращается на таком admission failure.

Безопасность cap имеет цену: held late attempt уменьшает доступную timed
concurrency. Это документированное opt-in backpressure, а не принудительная
остановка transformer. Admission очередь ограничена ordinary workers;
не создавать отдельную неограниченную очередь retry задач.

Все новые options проходят defensive snapshot/materialization для modern и
compatibility entry points; policy instances не содержат mutable runtime state.
Новые APIs записываются в PublicAPI.Unshipped; Shipped и immutable package
baselines не регенерируются для подгонки результата.

## O1: allocation gates

Перед production diff снять baseline на указанном SHA с идентичным benchmark
harness. Матрица: stages 1/4/16 × observers 0/1 × sink 0/1 × concurrency 1/8/32
× sync/async ValueTask = 72 случая. Report B/item, Gen0, throughput и отдельный
item p99; BenchmarkDotNet p99 целого batch нельзя выдавать за item p99.
Benchmarks реально проверяют item count/checksum и sink writes.

Добавить internal observer-interest gate **до** `new PipelineEvent`.
Предпочтительна консервативная immutable проверка наличия registered observers:
после RemoveObserver возможны лишние allocations, зато gate не скрывает buffered
worker fault/state. Gate не отменяет Meter/ActivitySource или metrics recorder.
Изменение только внутри EmitAsync уже слишком поздно для экономии event allocation.

`PipelineResult<T>` — struct; heap allocation в output path относится к
`PipelineOutput<T>` (sealed record). В PipelineOutputEmitter добавить
ShouldEmit(PipelineResultKind), сохраняющий modern/compatibility policy matrix,
и проверять его до создания PipelineOutput для всех terminal kinds.
Existing ShouldEmit(PipelineResult<T>) сохраняет прежнее поведение даже для
default result struct; kind gate применяется только к известным valid terminal kinds.
Sink write всегда выполняется до emitted success; failure sink не создаёт success.
Backpressure, drop accounting и exception behavior emitted outputs сохраняются.
Без registrations unused observer queue не получает events и не создаёт
искусственные observer drops; accounting configured observer deliveries сохраняется.

Дополнительно проверить representative Inline/BufferedReliable/BestEffort,
telemetry listeners on/off, failure/filter/skip, LineageMode и legacy OutputMode.
Не менять envelope representation/lineage и не вводить pooling в эту часть.

## O2: точное окно и optional bucket mode

Текущее окно уже использует FIFO Queue, ordered timestamps под lock и
incremental failure count. Старый O(n) пересчёт исправлен раньше; historical
ReleaseHardening benchmark numbers не являются новым baseline.

Сначала измерить steady expiry, burst после idle, retained capacity после peak,
и lock contention при 1/8/32 threads. В exact mode batch cleanup удаляет expired
prefix под одним lock при одном captured now, сохраняя включённую границу
elapsed == SamplingDuration, EWMA synthetic samples, half-open generations,
permit release, Reset и metrics. Batch cleanup само по себе не обещает уменьшить
retained Queue capacity или O(rate × window) память.

Если retained memory exact mode остаётся реальным ограничением, отдельный
feature PR вводит opt-in `CircuitBreakerSamplingMode` (`Exact = 0`, `Bucketed = 1`)
в CircuitBreakerOptions и CircuitBreakerPolicy; legacy constructors всегда Exact.
`SamplingBucketCount` default 64, допустимо 2..4096; ring имеет максимум count+1
live buckets, long total/failure counters, width = ceil(windowTicks/count).
Окно меньше count ticks использует width 1 tick. Mode требует положительное
finite effective sampling window; validation выполняется до activation.

Bucket включает oldest partial bucket: временная погрешность меньше width,
а не гарантированная погрешность ratio 1/count. Burst на границе способен
заметно изменить решение. EWMA formula и half-open state machine одинаковы
в обоих modes. Exact остаётся default; не переключать существующие runs молча.
Oracle сравнивает exact и buckets на одинаковом stream и отдельно вычисляет
вклад oldest boundary bucket. Расхождения totals/ratio/Closed→Open допустимы
только там, где этот вклад объясняет difference; half-open/probe contracts
совпадают без приближений. Проверить lazy rotation после длительного idle,
Reset, concurrent timestamp order и overflow-safe boundary arithmetic.

Bucket mode принимается только с ограниченной памятью и измеренной потребностью;
если gate не пройден, O2 завершается exact cleanup и измерениями, а bucket
feature остаётся непоставленной экспериментальной частью.

SDK: ровно global.json, сейчас 10.0.401. Локально dotnet отсутствует:
в этом design-only шаге build/tests/benchmarks не выполнялись.

cases и real DI scope regression — обязательные контрольные suites, затем
Core/Hosting/DI, correctness/concurrency/repeats, API/package/consumers/trim/AOT
и docs gates. Новые feature suites получают собственные nonzero count gates.

Performance evidence: same host/SDK/runtime/settings, baseline и candidate SHAs,
raw BenchmarkDotNet JSON/CSV и отдельный item-latency artifact. Disabled policies
не добавляют per-item heap allocations; throughput/p99 ухудшение более 5%,
подтверждённое повторными paired runs за пределами noise, блокирует принятие.
Claims об улучшении делаются только после фактических измерений.
